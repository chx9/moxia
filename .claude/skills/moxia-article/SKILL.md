# 新建墨匣文章

用户只提供原文（可能是粘贴的文字、语音转写、笔记，或一个文件路径）。你的任务是**只整理格式、不改写内容**，产出一篇可直接在墨匣中排版、复制到公众号的 Markdown 文章。

## 1. 获取原文

- 参数或对话中直接给出文字 → 用它。
- 给出文件路径（`.txt`、`.md`、`.docx` 等）→ 读取文件；`.docx` 可用 `textutil -convert txt -stdout <文件>` 转为纯文本。
- 什么都没给 → 请用户粘贴原文，不要自己编写内容。

## 2. 内容原则（最重要）

- **保留作者的原话**：不增删观点、不扩写、不总结、不润色语气，不替作者补充例子或结论。
- 只允许以下改动：
  - 修正明显的错别字、重复字、语音转写错误（如「的地得」误用、同音错字）；
  - 补全或规范标点；
  - 拆分过长的段落、合并被错误断开的句子；
  - 为结构添加标题（标题文字尽量取自原文的关键句或关键词）。
- 原文含义不确定时保持原样，在最后的汇报中列出存疑之处，不要猜。

## 3. 文章结构

```markdown
---
title: 文章标题
author: 作者（原文或对话中能确定时才填，否则省略）
description: 一句话摘要，60 字以内，尽量取自原文
label: 栏目标签（可选，显示在文首，如 MONEY & LIFE · 理财小课堂）
footer: 文末署名（可选）
---

导语段落（可选：原文开头若有引出全文的段落，保持在最前面，不加标题）

## 第一部分标题

正文……

### 小节标题

正文……
```

- **标题写在 front matter 的 `title` 中，正文不再写 `#` 一级标题**——公众号后台有独立的标题栏，正文重复会显得累赘。若用户明确要求正文带大标题，再加 `# 标题`。
- 正文从 `##` 开始，最多用到 `###`；短文（约 800 字以内）通常不需要小标题，不要为了结构而硬加。
- 每个 `##` 小节最好在 3–8 段之间；标题简短（一般不超过 15 字），同级标题句式尽量一致。
- 原文没有标题时，根据内容自拟 `title`，并在汇报中说明。

## 4. 墨匣支持的 Markdown

可放心使用：

| 写法 | 用途 |
| --- | --- |
| `**加粗**` | 每段最多一两处真正的关键句，全文不宜过多 |
| `> 引用` | 原文中的引语、他人原话、金句 |
| `- ` / `1. ` 列表 | 原文中本就是并列项、步骤的内容 |
| 表格 | 原文中有明确的对比、参数、清单数据时 |
| ` ```语言 ` 代码块 | 代码、命令、配置；务必标注语言（`swift`、`bash`、`json`…） |
| `` `行内代码` `` | 文中提到的命令、函数名、文件名 |
| `$E=mc^2$`、`$$…$$` | 数学公式 |
| `---` | 分隔差异较大的两部分内容（少用） |
| `> [!TIP] 标题` 换行接 `> 正文` | 提示框；`NOTE` / `TIP` / `IMPORTANT` 为重点提示，`WARNING` / `CAUTION` 为风险提醒 |
| ` ```cards ` 每行 `标签 \| 数值 \| 说明` | 数据卡片，一行 2–3 张为宜；数据必须来自原文 |
| ` ```chart ` 每行 `标签 \| 数值`，可加 `title:` / `note:` 行 | 柱状图；数据必须来自原文，不得编造 |
| `[文字](https://…)` | 外链，墨匣复制时会自动转为文末「参考链接」脚注 |
| `![图注](路径或网址)` | 图片；独占一行时居中，alt 文字作为图注 |

**不要使用**（墨匣不支持或公众号会丢弃）：HTML 标签与内联样式、`[^1]` 脚注语法、`- [ ]` 任务列表、Emoji 短码（`:smile:`）、多级嵌套超过两层的列表。

图片：原文中提到「此处配图」「见下图」等时，在相应位置插入 `![图片说明](图片待补充.png)` 作为占位，复制时墨匣会把它显示成「图片待上传」占位框，方便作者在公众号中补图。不要编造图片网址。

## 5. 中文排版规范

- 中文与英文、数字之间加一个半角空格：`使用 Swift 编写`、`共 3 个步骤`；数字与单位之间不加（`10GB`、`20%`），中文与全角标点之间不加。
- 中文语境用全角标点（，。：；！？「」（））；整句为英文时使用半角标点。
- 引号统一用直角引号「」，嵌套用『』。
- 省略号用 `……`，破折号用 `——`。
- 专有名词使用正确大小写：GitHub、iOS、macOS、JavaScript、微信公众号。
- 段落之间空一行；不要用空格或全角空格做首行缩进（缩进可在墨匣设置中开启）。

## 6. 保存与打开

1. 文件名：`YYYY-MM-DD-标题.md`（今天的日期；标题去掉 `/ : ? * " < > |` 等字符，过长时截取前 30 字）。
2. 保存位置：用户指定的路径优先；否则保存到 `~/Documents/Moxia/`（不存在时创建）。不要覆盖已有文件——重名时在文件名后加 `-2`、`-3`。
3. 在墨匣中打开：

   ```bash
   open -b app.moxia.Moxia "<文件路径>" 2>/dev/null || open -a Moxia "<文件路径>"
   ```

   两条都失败时（未安装或未构建），告诉用户文件位置，提示可在本项目中运行 `./scripts/build-app.sh` 后再打开。若墨匣中有未保存的修改，墨匣会先询问是否保存。

## 7. 完成后的汇报

简短告诉用户：

- 文件保存路径；
- 文章结构（各 `##` 标题列表）；
- 做过的文字修正（错别字、标点等，逐条列出；没有则说明「未改动文字」）；
- 存疑、需作者确认的地方，以及插入的图片占位；
- 推荐主题（一句话理由）：人文随笔 → 墨韵；通用 → 素笺；技术与产品 → 晴空；生活与读书 → 拾光；设计与评论 → 格律。
